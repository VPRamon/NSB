# Complete adaptive schedule measurements

Both algorithms are compiled into one release benchmark binary: the recorded production adaptive call graph and the unchanged test-only scanner, using the registry Siderust 0.14 / Tempoch 0.10 graph, paired fixed worker/core assignments per group (two Rayon threads on two performance cores for three groups; four threads on four efficiency cores for South K&S), three alternating timed repetitions after warmup. Both methods return usable native UTC schedules. The recorded core time includes target preparation, physical partitioning and UTC conversion; end-to-end time adds the measured shared site preparation once. It excludes process startup, JSON formatting and I/O. An existing evaluator is reused; immutable model and fixture construction are outside library timers. CLI process measurements include construction and are reported separately.

CTAO-N/S, both lunar models, 1/7/30/365 days, 1/10/100 targets, every mask, actual ALL and explicit four-component composition are included. Starlight is a synthetic configured benchmark fixture, never an admitted production asset. For compositions including Starlight, each target's cached Starlight contribution is added to the nominal threshold so dynamic components still cross; pure Starlight keeps the nominal threshold.

Compared against 600 s and 30 s (single target) / 120 s (batches) authoritative scanners. Those references are discrete evidence, not mathematical completeness proofs. Every validated coarse boundary witness is retained within 0.533 s; specifically verified singleton jump artifacts are counted separately. Fine-reference topology differences require independent dense local validation of every additional rejected excursion (including physical-window edges); unexplained differences fail before any row is emitted. The separate adversarial tests resolve the approximately 53 ms Zodiacal event and 2.4 s Airglow/Moonlight excursion with local 1 ms references.

Three repetitions support medians and observed ranges, not statistical p95 estimates. Raw values, duration sums, exact evaluations, fits, subdivisions, root refinements, bracket widths, resource limits, peak pending work and process RSS high-water marks are in [JSONL](production.jsonl); the [environment](environment.json) records hardware and compiler. RSS is cumulative whole-process VmHWM, not a per-algorithm memory comparison. Cache byte counts are active sample payload, excluding allocator/capacity overhead. Exact counts are integrated search probes; target/site preparation is included in time but not in those counts. Batch counters and duration sums aggregate target queries; budgets apply to each ThresholdQuery, while peaks are maxima across targets.
