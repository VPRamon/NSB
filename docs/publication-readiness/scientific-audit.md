**Composition caveat:** ordinary `evaluate` sums selected model contributions, but the existence of numeric component totals is not evidence of a completely equivalent ground-level sky observable (notably TOA starlight). `integrate_band_components` is stricter: wavelength 300–650 nm, restricted Zodiacal + Airglow, Moon only if physically zero, **Starlight rejected**. It does not return calibrated filter magnitudes or complete synthetic spectra. B/V=S10 values at 445/551 nm are central-wavelength **proxies**, not Johnson passband outputs.

## Numerical and software design audit

- Dimensional basis: typed qtty radiometry; separated UTC/time, coordinates/units delegated to **Siderust/Tempoch** rather than original NSB scientific inventions. Distinguish `R` for an integrated line from `R/nm` continuum. Refer to [metadata](https://github.com/VPRamon/NSB/blob/57584ee298f25f8af7a6f169d71e87f8a59eea9a/docs/specifications/scientific-metadata.md).
- Source-vs-transport provenance: atmospheric identity is not a new source model; `Direct` permits TOA inputs but rejects atmospheric emitters and already scattered lunar paths. Transport selection is not a calibrated site claim.
- Numerical verification: explicit component-sum identity, selected analytic/independent references, source-asset hashes, band support guards, synthetic convergence/limiting cases, and reference comparisons. Single-scattering independent SciPy fixtures and HEALPix angular tests are *numerical*, not empirical, validation.
- First-order reference has stated work/memory caps (250M conservative work units/8 MiB scratch), deterministic accumulated integration, separately exposed direct/single radiances, higher orders unknown. Documented explicit convergence failures avoid false success.
- Offline producer `nsb-data-tools` prepares and checks scientific assets; runtime does not fetch data. Rust, PyO3/ABI3 Python and CLI reuse scientific core. A claim of **cross-interface numeric equality** requires pinned installed-wheel + CLI tests for the actual submitted release; source architecture alone does not prove it.
- Planning: typed threshold query prepares Sun, astronomical-night, target, and Moon intervals, then adaptively samples authoritative evaluator with bracketed crossing refinement and fallback. Numerical speedups cannot be turned into scientific accuracy.
- **Release obstacle**: root Cargo [patch](https://github.com/VPRamon/NSB/blob/57584ee298f25f8af7a6f169d71e87f8a59eea9a/Cargo.toml) pins Siderust Git revision `83d1ebb29ca1ae0b327d5784d13eda231d52c120`; [#265](https://github.com/VPRamon/NSB/issues/265) states registry/PyPI packaging is blocked pending an upstream release. Do not claim `0.1.1` is independently clean-installable from registries before verifying.

## What is and is not new

**Candidate central contribution:** an auditable, typed, component-resolved Rust scientific engine with consistent Rust/Python/CLI point and planning interfaces, fail-closed scientific-asset admission and explicit physical-maturity/uncertainty metadata. This is a **methodological and software contribution**, not proof of new emission physics.

**Potential scientific-method extensions (conditional):** explicit separation of input source/transport/measurement operators, independent bounded numerical scattering references, and restricted-band admission gates. These have value when presented against existing alternatives, with validated-domain and solver limitations exposed.

**Dependency boundaries:** Siderust owns astronomy coordinate/time/atmosphere primitives, Optica phase/optical quantities, qtty quantities. HEALPix, Noll, Jones, Leinert, PALACE and classical radiative transfer are established. NSB's contribution is its composition, assets/admission, interfaces, orchestration, specific verified algorithms and failure semantics, not these foundational ideas.
