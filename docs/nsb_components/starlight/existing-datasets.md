# Provenance of existing starlight datasets

Status: Historical provenance record.
Audience: Maintainers, scientific reviewers, and users auditing bundled data.
Scope: Starlight artifacts currently registered in `crates/nsb/data/`.

This record distinguishes evidence retained in the repository from the
supported procedure for producing a new candidate. It must not be read as a
claim that every existing artifact can be regenerated byte-for-byte from the
repository alone.

### Issue #72 conservative-resolution replacement

The original nside-256 and nside-512 generator copied the complete integrated
parent-pixel flux and source counters to every child. Their all-sky flux and
counts were therefore multiplied by approximately 4 and 16. The replacement
published by the PR closing issue #72 keeps `flux_ph_m2_s` as integrated flux
per pixel, divides it uniformly among equal-area NESTED children, and
deterministically apportions integer counters. The latter preserves accounting
but is not evidence of sub-pixel source position.

All four CSVs now carry the explicit v2 quantity, unit, ordering, derivation,
and source-count headers. This deliberate header versioning changes the
nside-64 and nside-128 checksums without changing their scientific row values.
The v3 merge report records totals calculated from each emitted map and their
relative drift from canonical nside 128. All four current totals are
`8.646151809493544e12 ph m-2 s-1`, with zero recorded drift and exact totals of
219,109,593 admitted and 88,049 excluded sources.

### Retained evidence

- The source family is the official Gaia DR3 GaiaSource and XP continuous bulk
  distributions, paired by the 3,386 source-range partitions listed in
  `merge_report.json`.
- The pipeline used the frozen GaiaXPy 2.1.4 continuous-design fixture and the
  `gaia-dr3-xp-continuous-join-v1` admission policy.
- The report records 219,197,642 observed sources, 219,109,593 admitted
  sources, and 88,049 exclusions, all classified as `invalid_flux`.
- The target map is Galactic HEALPix nside 128. The nside 64 map is a
  downsample; nside 256 and 512 are diagnostic upsampled products, not
  independently resolved maps.
- Population weights remained one because no validated Gaia selection-function
  correction was applied.
- Flux was directly integrated over 336–650 nm. No independently calibrated
  300–336 nm correction was applied.
- The report records output checksums and a stable independent partial-merge
  checksum.
- The artifacts are registered as `candidate` and `runtime_embedded = false`.
  They are not admitted as bundled production starlight.

### Evidence not retained

The original lifecycle `run.json`, `validation.json`, normalized inventory
files, acquisition receipts, configuration checksum, run identifier, generator
Git revision, and exact command line were not committed. The working dataset
workspace was site-local and is not part of the repository.

Consequently, the checked-in maps have integrity and scientific-policy evidence
but not a complete self-contained byte-for-byte reproduction bundle. The
placeholder generation command formerly recorded in the asset registry must
not be interpreted as the command that produced these exact bytes.

### Supported regeneration procedure

A new candidate must be generated from a fresh workspace using
`crates/nsb-data-tools/config/starlight-production.toml` and the documented
`update → build → validate → publish` lifecycle. Follow
[Starlight dataset generation](map-generation.md) and the
[maintainer runbook](../../maintainer-guide/datasets.md). A regenerated
candidate may differ if Gaia inventories, pipeline code, configuration, or
admission policy differ; such output is a new dataset version and must not
silently replace these checksums.

## Experimental manual seed

`starlight_manual_seed_v1.csv` has SHA-256
`a18c41ceeaaaf343e6991d6a718b6edf0b8cbfc46faf1cfaf7551c3d1c434668`.
It is a 12-pixel nside-1 manually curated Tycho/Hipparcos-style bright-star
seed. Its header records a nominal generation date of 2026-06-22 and describes
the proxy photometry and band convention.

No released source catalogue, source-row list, or executable generation input
was retained. The seed therefore cannot be independently regenerated from
repository inputs. It is intentionally marked `experimental`, is selected only
through the explicit experimental runtime path, and must not be promoted by
reproducing or repackaging the same bytes.

## Required evidence for future publications

Future candidate publications must retain a sanitized provenance bundle
alongside the map and merge report containing:

- the lifecycle run manifest and validation report;
- generator Git commit, UTC generation time, exact command, and configuration
  checksum;
- normalized Gaia inventory checksums and a deterministic root checksum over
  acquisition receipts;
- source and calibration fixture versions and checksums;
- all published artifact checksums and the scientific-policy identifiers;
- any independent comparison report and redistribution decision.

Site paths, scheduler account names, user names, and credentials must be
removed from the retained copies. Publishing should fail if the provenance
bundle is missing or does not match the artifacts.
